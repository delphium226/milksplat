# Core engine: decisions made during implementation

Every judgement call made on the project's behalf while building sub-project 1 (2026-11-07 to 2026-11-08), in the order made. Each line gives the decision, the reason, and what it costs if it turns out wrong. Revisit any you disagree with.

- **R1** ms-render defines its own `FeedbackFormat { Rgba8, Fp16 }`; ms-preset keeps its own enum; ms-engine maps between them — spec §3.1 forbids ms-render knowing presets — cost if wrong: a trivial duplicate enum.
- **R2** each call argument may be a `;`-separated sequence (parsed as a Block), as in EEL2 — needed for `while(...)`/`loop(n, a; b)` idioms and .milk compatibility — cost if wrong: small parser change.
- **R3** Task 14 introduces the full `Uniforms` struct (field list from Task 15) and a `WarpShader` with only a `builtin` constructor; Task 15 adds user-shader compilation and the layout test — avoids a forward reference — cost if wrong: Task 15 edits Task 14's types.
- **R4** Task 15 implements shader compilation on `RendererShared` (Clone + Send + Sync, from `Renderer::shared()`); `Renderer::compile_shaders` delegates to it — the loader thread (Task 22) needs it without &Renderer — cost if wrong: an extra wrapper type.
- **R5** golden checks are a macro `ms_render::assert_golden!(img, "name")` expanding to `ms_render::golden::check(&img, env!("CARGO_MANIFEST_DIR"), "name")`, so goldens live under the calling crate's tests/golden — cost if wrong: call-site churn.
- **R6** Task 22 creates a minimal `presets/default.splat` (gentle zoom + main wave, no shaders); Task 25 may refine it — cost if wrong: none.
- **R7** Task 23 creates `config.rs` with the full `Config` struct from Task 24 plus `Default`; Task 24 adds load/save and the rest — cost if wrong: none.
- **R8** `milksplat` has both `src/lib.rs` (all modules, pub) and a thin `src/main.rs`, so integration tests can import it — cost if wrong: none.
- **R9** replace the 2/11 assertion with: over 20k picks in a 10-preset library with 1 favourite, favourite count / mean non-favourite count is within [1.5, 2.5] — the recency rule makes an exact 2/11 untrue — cost if wrong: weaker test.
- **R10** no `? :` ternary in the language — spec §5.1 lists operators without it; the .milk importer (sub-project 4) translates ternaries to if() — cost if wrong: add a parser rule later.
- **R11** parser nesting depth capped at 256 with a CompileError — hostile/garbage preset input must not overflow the stack (global no-panic constraint) — cost if wrong: legit presets nested >256 deep fail (none known).
- **R12** truthiness everywhere (&&, ||, !, if, while) is fuzzy: |x| < 1e-5 is false — matches EEL2's close-factor behaviour and keeps ! consistent; spec §5.1 says 'any other value is true' — cost if wrong: values in (0,1e-5) treated as false.
- **R13** max AST depth 1024 enforced in the parser incl. left-deep binary chains, rejected before construction — compiler and Drop recurse per node; 1 MB Windows main stack — cost if wrong: a legit expression with >1024 chained terms fails to compile.
- **R14** promoted Task 3 reviewer Minor "constant-folded tests never execute VM dispatch" to Important — VM opcode paths would otherwise be untested — cost if wrong: one extra fix round.
- **R15** preset compilation runs only on threads with >= 16 MB stack (loader thread in Task 22; tests that compile deep fixtures spawn such a thread) — 1024-deep ASTs only just fit 2 MB in debug — cost if wrong: none (stack is reserved, not committed).
- **R16** megabuf/gmegabuf support compound assignment (`megabuf(i) += v`) via a new Expr::MemAssign, index evaluated once — EEL2 allows it and .milk presets use it — cost if wrong: small parser/compiler extra.
- **R17** builtin domain errors never yield NaN: sqrt(|x|), asin/acos outside [-1,1] -> 0, log/log10(x<=0) -> 0; loop() value 0; while() value = last body value — EEL2 sqrt uses |x|; others chosen for safety (engine also sanitises) — cost if wrong: imported presets relying on NaN/-inf propagation differ slightly.
- **R18** a pure builtin returning NaN from non-NaN inputs returns 0 instead (sigmoid with NaN product returns 0.5) — extends R17 consistently — cost if wrong: minor .milk divergence.
- **R19** run_batched on a non-batchable program falls back to scalar per lane in order (debug_assert) — never wrong results — cost if wrong: none.
- **R20** AudioHistory timing — capture_time is the last frame's time; gaps > 50 ms between packets are zero-padded; jitter/overlap appended without reordering; window() uses nearest whole frame, no interpolation; silent_for origin = first data time — spec §8.2/§8.3 silent on these details — cost if wrong: small timing offsets.
- **R21** raw band energies exposed as #[doc(hidden)] pub fn raw_energy() — plan said #[cfg(test)], which integration tests cannot see — cost if wrong: one hidden pub fn.
- **R22** before the first non-silent tick, bass/mid/treb and _att read 0.0 (silence looks quiet); band energy sums the full rfft range; wave is channel-major [[f32;576];2] — spec silent — cost if wrong: brief startup difference.
- **R23** band long-term averages are frozen on silent ticks (energy sum < 1e-9 or silent_for > 0.1 s) and warm up as a running mean (weight max(1-exp(-dt/5), 1/n)) — plan's "init from first non-silent tick" inflated bands on every start/resume — cost if wrong: slightly slower adaptation when a track's loudness changes in its first ~5 s.
- **R24** onset/resume regression tests bound instant bass < 4 (pink-noise bass legitimately swings to ~2.7 per tick), mid/treb/_att within 0.5..2.0, _att lower bound waived 0.75 s after onset — physically justified, defect (11-21x) still caught — cost if wrong: weaker bass bound.
- **R25** beat detector skips silent ticks (no flux pushed, no beat), resets prev bass energy on the first non-silent tick so music onset can register, requires >= 10 flux values before any beat, uses population std and tick time — spec §8.3 silent on these — cost if wrong: first beat after silence may differ.
- **R26** beat onset tolerance 20.1 ms (measured constant 19.98 ms lag from Hann window tail + 10 ms packet timing) accepted; kick tests use a -60 dBFS noise bed — pure digital silence between kicks gives 40 ms lag, acceptable — cost if wrong: test slightly looser than plan's ±1 tick.
- **R27** Stamp gains `dropped_tail: u32`; a packet that doesn't fit keeps its head and drops its tail; a full stamp ring drops the whole packet; drain_into computes last-written-frame time with hist.sample_rate() — producer doesn't know the rate; keeps frames/stamps in sync — cost if wrong: none (internal type).
- **R28** all six library crates are declared in root [workspace.dependencies] (path + version) and used via .workspace = true — Global Constraint "declare once" applies to intra-workspace deps too — cost if wrong: none.
- **R29** Task 10's manual checks (music playing, switching the default device) are deferred to the user / release checklist; the implementer runs the meter and ignored smoke test automatically — an agent cannot switch Windows audio devices — cost if wrong: device-switch restart unverified until the user tries it.
- **R30** the capture callback may allocate only to grow its downmix scratch when a buffer larger than ever seen arrives (documented) — buffer sizes are not known before the first callback — cost if wrong: one rare allocation on the audio thread.
- **R31** treat BTHHFENUM (Bluetooth hands-free) as Bluetooth too, alongside BTHENUM/BTHLEDEVICE — reviewer flagged HFP endpoints likely missed; fix in final wave — cost if wrong: a non-BT device with that enumerator gets a 200 ms default offset (none known).
- **R32** .splat non-numeric value for a numeric key is a warning (default used), not an error; Params.values holds only keys the file set, with Params::param() applying PARAM_DEFAULTS; wave/shape numeric keys pass through unwarned — tolerant loading suits hand-written presets — cost if wrong: typos in wave/shape params go unflagged until compile.
- **R33** PARAM_DEFAULTS uses a fixed table following MilkDrop where 0 is broken (wave_x/y 0.5, mv_x 12, mv_y 9, mv_l 0.9, ob/ib_size 0.01, ib rgb 0.25, wave_brighten 1, texture_wrap 1, warp 1, gamma 1) — plan's "everything else 0" contradicted spec "MilkDrop default"; gamma kept at 1 (MilkDrop's 2.0) since importer writes explicit values — cost if wrong: native preset defaults differ from MilkDrop.
- **R34** sim_rate clamped to [1, 240] with a warning — engine needs a sane range — cost if wrong: none.
- **R35** BUILTIN_VARS order = read-only main, writable main (PARAM_DEFAULTS order), wave/shape locals (deduped), q1-32, t1-8, reg00-99; builtin_var_table() seeds every program table — engine relies on stable VarIds — cost if wrong: none.
- **R36** Library::scan keeps the first occurrence of an id; callers pass the user presets root before the bundled root so user presets override bundled ones — cost if wrong: a user can shadow a bundled preset (intended).
- **R37** golden harness exposes #[doc(hidden)] check_with(actual, dir, name, bless) so tests never mutate MS_BLESS process env (parallel tests) — cost if wrong: none.
- **R38** Gpu uses DX12 first and touches Vulkan only when DX12 has no hardware adapter, in both headless() and the windowed path; windowed code uses Gpu::create_instance() + Gpu::with_instance(instance, surface) (surfaces are tied to their instance); later render tests use Gpu::headless() — parallel Vulkan instance creation crashes this machine's driver — cost if wrong: Vulkan-only systems (rare on Windows) less tested.
- **R39** all blocking GPU polls go through Gpu::poll_wait(), which returns early when lost and wraps device.poll in catch_unwind (wgpu 30 panics in poll on device loss), marking the device lost — global no-panic-on-GPU-errors constraint — cost if wrong: a caught panic may leave wgpu in odd state, but the device is recreated anyway.
- **R40** warp mesh UV space has v=0 at top (texture space); builtin warp = sample(prev, uv).rgb * decay * vertex colour, sampled with s_fw (wrap); layers blend additively onto a cleared target with alpha written as 1; bind group 0 layout fixed now (0 Uniforms, 1 sampler_main, 11 s_fw, 12 s_fc) for Task 15 reuse — cost if wrong: Task 15 adjusts the layout.
- **R41** accept implementer's blend (shader alpha = layer weight; colour SrcAlpha/One; alpha Zero/One on target cleared to alpha 1) over R40's wording — R40 as written would drop weights / give alpha 2 in Fp16 — cost if wrong: none.
- **R42** golden test patterns for multi-pass feedback use soft (pre-blurred) edges so NVIDIA vs WARP bilinear precision differences stay under tolerance — cost if wrong: goldens less sensitive to hard-edge sampling bugs; AMD/Intel untested.
- **R43** Task 15 — one shared group-0 layout for warp and composite; bindings 2-10 get placeholder textures until Task 16; user texture prefixes fw_/fc_/pw_/pc_ (none = fw_); missing user texture → white placeholder + error (no fallback); >16 user textures → stage falls back; composite draws the first layer opaque and later layers SrcAlpha/OneMinusSrcAlpha; gamma = pow(c, 1/gamma) — spec silent on these — cost if wrong: small visual differences vs MilkDrop.
- **R44** keep naga uniformity analysis on; preset shaders must use textureSampleLevel inside non-uniform branches (README/preset docs and the .milk importer must handle this) — WGSL rule, disabling is not supported — cost if wrong: some hand-written shaders fall back until fixed.
- **R45** compile_shaders takes the composite target format and builds that pipeline on the loader thread inside error scopes; composite()'s lazy per-format path stays only as a logged safety net — spec §6.1 no-hitch rule — cost if wrong: a window format change triggers one render-thread compile.
- **R46** texture names containing path separators, '..' or a drive colon are rejected; images > 64 MB rejected and > 4096 px downscaled; randNN uses resolve_with(name, rng) and stays consistent per preset; blur levels match feedback format and blur the previous level with a 9-tap Gaussian — presets are untrusted (must not read arbitrary files) — cost if wrong: legit texture names with those characters fail.
- **R47** TextureResolver is stateless/shareable; per-preset random picks live in a caller-owned PresetPicks { rng, picks } seeded from the preset seed XOR a constant (separate stream from the VM's rand) — a shared loader resolver otherwise fixes rand picks per process — cost if wrong: none.
- **R48** image decode limits max_alloc 256 MiB, max dimension 8192, downscale to <= 4096 via an 8-bit path — a 1.3 MB PNG could otherwise allocate ~1.3 GiB and abort — cost if wrong: textures between 8192 and 16384 px are rejected instead of downscaled.
- **R49** accept dev/test opt-level 3 for image codec crates (profile.dev.package) and thumbnail_exact box-filter downscale — test speed and debug performance — cost if wrong: slightly slower clean dev builds.
- **R50** Task 17 — main wave modes written as original code from our own descriptions (not transcribed from MilkDrop); textured shapes sample the PREVIOUS feedback buffer (never the draw target); premultiplied-over for normal draws, SrcAlpha/One for additive, alpha kept 1; line width 1/2 px scaled by target_height/1080; borders sized as a fraction of each axis; v1 motion vectors point toward screen centre (no real motion sampling) — avoids read/write hazard and copying; spec silent on details — cost if wrong: visual differences vs MilkDrop for imported presets, tunable in sub-project 4.
- **R51** text pipelines may be created lazily per target format (built-in fixed WGSL, logged); recreate rebuilds every GPU object and stale RendererShared/ShaderSet/WarpShader must fail safely (no panic); recompile lives on RendererShared (loader thread) with a Renderer wrapper taking comp_format and tex — cost if wrong: one render-thread text pipeline compile per new format.
- **R52** FixedClock clamps rate to [1, 240], ignores bad dt, keeps phase on set_rate; Governor needs >= 1.5 s of samples before deciding, clears its window after each step, uses a fixed 512-sample ring — spec §6.6 gives thresholds only — cost if wrong: governor reacts ~0.5 s later than the plan's "after 2 s".
- **R53** governor_steps_down test uses 16 ms (plan's 15 ms vs 16.7 ms budget can't exceed 0.9x) — plan arithmetic error — cost if wrong: none.
- **R54** accept due = floor(total*rate + 1e-9) (1e-9 tick epsilon) — plain floor still misses exact boundaries (3/47*47 = 2.9999999999999996) — cost if wrong: a dt 1e-9 tick short of a boundary counts as reaching it (invisible).
- **R55** Task 20 — vertex x = col/cols, y = 1 - row/rows (bottom-up), rad/ang computed with aspect applied; warp UV formula is an original approximation (documented, tuned in sub-project 4); mesh colour all 1s in v1; shape defaults r=1,g=0,b=0,a=1, r2=0,g2=1,b2=0,a2=0, border rgb 1 a 0.1, tex_zoom 1; roam_cos/sin = cos/sin(time*[0.3,1.3,5,20]); loop-cap warning once per block per instance; tick may return &TickOutput to avoid allocation — spec gives structure not exact formulas — cost if wrong: imported presets look different until tuned.
- **R56** accept ms-expr API additions BatchScratch/run_batched_with and Program::compact_vars (needed for allocation-free batching) and treating reg/t vars as carried for batching (more scalar, always correct) — cost if wrong: none.
- **R57** preset init (main + waves/shapes) is deferred to the first tick, which has &mut Globals; new() keeps its signature so the loader thread can build instances — spec §5.2 globals rule — cost if wrong: init cost lands on the first render tick (small).
- **R58** wave `point` code stays scalar in v1 (spec §5.4 says batched; ≤ 512 points × 4 waves is cheap) — cost if wrong: minor CPU cost.
- **R59** `samples` is a wave built-in (wave frame code may set it, as in MilkDrop), not a user variable — cost if wrong: a preset using `samples` as its own variable sees it reset.
- **R60** blend pattern formulas fixed (RadialIn/Out on d=dist/sqrt(0.5), Sweep projection, Plasma 2-octave value noise at scales 4/8), mesh mixing resamples the smaller mesh bilinearly, render_blend/composite_layers helpers live in blend.rs for the director — spec §7.1 names patterns only — cost if wrong: transitions look different from MilkDrop's.
- **R61** Task 22 — loader thread 16 MB stack "ms-loader", 1 MB preset file cap, per-request catch_unwind, PresetPicks seeded preset_seed ^ 0x5EED_7E47; director owns tick_and_render/composite helpers so the app doesn't re-implement blend logic; newer requests supersede pending ones (stale Ready ignored); a switch during a blend is queued; blend_s <= 0 → instant; failures capped at 10 consecutive then retry after 10 s; default preset never blocklisted; on_renderer_recreated recompiles current/pending shaders — spec §7 silent on these — cost if wrong: different switching feel.
- **R62** accept RendererShared::warm_up (+ poll_wait_on, lost flag) in ms-render, Director::new taking &RendererShared + comp_format, LoadResult request tickets, director/ module split, auto-advance test over 30 s — needed for loader warm-up and stale-result handling — cost if wrong: none.
- **R63** Prev skips disallowed history entries; each Loader has a unique loader_id and the director re-sends pending requests to a new loader, plus a 30 s pending timeout; manual pending switch suppresses auto-advance/hard cuts; abandoned blend applies-or-drops its queued switch; device-lost load failures don't session-skip; non-finite now ignored — closes crash-loop bypass and stuck-director paths — cost if wrong: none.
- **R64** Task 23 — render thread "ms-render" with 16 MB stack owns Gpu/Renderer/Director/Loader/audio; non-sRGB Bgra8/Rgba8 surface format used as comp_format; GPU objects rebuilt as one GpuState unit on device loss and the old Gpu dropped everywhere (Task 18 stale-Gpu hazard); clock time base reset on resume from minimise; --exit-after/--log-fps flags for automated smoke runs; preset name shown 3 s after every change — cost if wrong: none significant.
- **R65** accept run_render_thread taking instance + RenderOptions, ToRender::NewSurface, device-loss rebuild via a new surface from the main thread + Renderer::new, monitor-rate frame pacer under Mailbox — winit/DX12 constraints found in testing — cost if wrong: slight pacing judder vs Fifo.
- **R66** Director::release_gpu() drops every held ShaderSet/WarpShader to CPU-only sources before the old GpuState is dropped; recovery order on_device_lost → release_gpu → drop GpuState → new surface → GpuState::new → on_renderer_recreated — D3D12 per-adapter device singleton would otherwise hand back the removed device — cost if wrong: none.
- **R67** Task 24 — panic hook only records the panic (no file/message box) because catch_unwind is used intentionally elsewhere; crash reports are written only when a panic escapes a thread boundary or main; config loaded field-by-field (bad field → default + warning), saved atomically via tmp+rename, debounced ≤ 1/s off the frame path, always on exit; known-folder paths via SHGetKnownFolderPath with env fallback; crashed-run preset skipped for the session only; --safe = empty library + no user shaders + default audio device; keep-awake from the main thread on state change; hot reload via notify 300 ms debounce, current preset swapped without blend, library rescanned; A/V offset per device clamped [-500, 2000] ms with Bluetooth default 200 — cost if wrong: none significant.
- **R68** accept Task 24 signature changes (hotreload::watch -> Option<Watch> with ids + library, RenderExit::Crashed, KnownDirs/from_dirs), marker debounce 250 ms, Loader::spawn_safe / Director::reload_current / set_library — cost if wrong: none.
- **R69** hot-reload roots made absolute with std::path::absolute and compared case-insensitively; run marker records showing + loading ids, written synchronously before risky work (switch start, load request), no debounce, both skipped next session; A/V offset range is [0, 2000] ms everywhere (amends R67's [-500, 2000]) — cost if wrong: none.
- **R70** Task 25 presets are original designs (no ported MilkDrop/projectM/Butterchurn equations); quality bar = varied palettes, mean luminance 0.05–0.85 over 600 ticks of synthetic music, no full-frame flashing above 3 Hz (photosensitivity); textures procedurally generated with a committed generator; WARP divergence fixed by softening looks, not loosening tolerance — cost if wrong: presets need retuning after real-music feedback.
- **R71** package.ps1 runs under PS 5.1 and pwsh, fails on cargo errors or a VCRUNTIME140 dependency (dumpbin via vswhere, warn if absent); README avoids MilkDrop/Winamp branding beyond one factual credit; checklist pre-ticks only items already verified (live audio capture, 60 fps on RTX 3090, simulated device-loss recovery) — cost if wrong: none.
- **R72** loop cap becomes a per-tick budget (1,048,576 iterations per tick per preset, shared by all runs incl. batched lanes) — per-execution cap let one line freeze the render thread for 30-40 s — cost if wrong: very loop-heavy presets get cut short per tick.
- **R73** on device loss, blame the preset being warmed up by the loader if one was in flight, else the shown preset if current < 2 s; the culprit is blocklisted and not re-sent — cost if wrong: none.
- **R74** GPU tests serialise through a process-wide test lock (ms_render::test_support::gpu_lock); package.ps1 keeps parallel tests — concurrent headless D3D12 devices crash/hang the test process — cost if wrong: slower GPU test suites.
- **R75** implement per-preset sim_rate (clock follows the shown preset; during a blend keeps the outgoing rate until it completes) rather than only warning — spec §3.3 requires it — cost if wrong: none.
- **R76** per-preset reactivity (Up/Down 0.25x–2.5x in 0.25 steps, Backspace resets; saved in `[preset_reactivity]` by preset id, 1x entries never stored; config-only global `reactivity` multiplies, product clamped to 0..=2.5): bands scale their deviation from 1 (`1 + k(v-1)`, ≥ 0), waveform scales about 0, spectrum (`ln(1+|X|/2)`, absolute, 0 in silence) scales proportionally; beat, beat_strength, silent_for and time untouched; level exactly 1 passes the frame through (bit-identical); flash guard: a turned-up value is held to max(ceiling, unscaled) with ceilings bands 3.0, wave 1.0, spectrum 3.0, verified at 2.5x on real techno (every bundled preset's max tick-to-tick luminance delta ≤ 0.06); during a blend each preset's code, uniforms and waves use its own level but the one spectrum texture carries the incoming preset's — cost if wrong: user shaders sampling the spectrum see the incoming level for the 2.7 s of a blend.
